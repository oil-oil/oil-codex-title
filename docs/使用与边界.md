# mogoo-codex-title

让 Codex 侧边栏的话题名称跟上实际讨论内容。

每轮对话结束后，插件在后台读取最近 3～5 轮有效对话与原始目标，由独立模型判断是否更新标题。标题使用「类别 emoji + 对象｜目标」，准确时保持原样。外层项目已提供名称时，标题默认省略重复项目名；monorepo 子项目、上级目录操作或跨项目歧义除外。

## 安装与开始使用

这是本地 Codex 插件，适用于支持生命周期 Hook 的桌面版本。需要 Python 3.10+ 和兼容 Codex CLI；默认官方模式需要登录，无需另外保存 API Key。默认使用 **GPT-5.6 Luna Fast，低推理档**（`service_tier=priority`），命名消耗当前账号的模型额度；Fast 会增加用量。此 fork 也支持显式配置中转站，见下文。

直接把下面这段话发给 Codex，让它查找仓库并完成安装：

```text
帮我从 GitHub 仓库 MogooStudio/oil-codex-title 安装为完整的 Codex 插件（包含 Stop Hook，不要只安装 Skill），使用仓库的 mogoo-codex-title 插件市场。请完成安装、启用 Hook，并运行 doctor 检查；如果需要我在界面中信任 Hook，请告诉我具体操作。
```

安装完成后：

从线上 fork 安装时，先执行 `codex plugin marketplace add MogooStudio/oil-codex-title --ref main`，再执行 `codex plugin add mogoo-codex-title@mogoo-codex-title`。后续使用 `codex plugin marketplace upgrade mogoo-codex-title` 刷新 Git 快照，再运行同一安装命令读取新版本。0.4.3 起插件、市场和技能统一使用新名称；从旧名称迁移前停用或卸载 `oil-codex-title@mogoo-oil-title` 等旧来源，避免重复 Hook。已配置 Windows worker 时，在新安装目录重新运行 `worker-setup`，更新同一个任务的缓存查找逻辑。配置和密钥环境变量独立于插件安装目录，更新时继续复用；完整步骤见 [README](../README.md#从旧名称或来源迁移)。

1. 让 Agent 执行插件中的 `doctor`，确认可执行文件和话题读取能力。
2. 确认 Codex 的 `features.hooks` 已开启；可通过 `codex features enable hooks` 开启。
3. 在 Codex 的 Hook 管理入口检查并信任本插件的 **Stop Hook**。CLI 使用 `/hooks`。安装插件本身不会自动信任 Hook。
4. 在新的正常对话中验收，等待后台模型返回后检查侧边栏标题与本地日志。

需要信任的行为：执行插件的 `scripts/mogoo_codex_title.py hook`，读取当前本地话题、调用独立临时命名模型，并通过官方 `thread/name/set` 更新标题。它不恢复原话题、不发送新消息、不直接改写话题数据库。

## 命名方式

默认在标题核心后追加 ` · MM-DD HH:mm`，表示最后一条用户消息的发送 / 创建时间，使用本机时区。消息时间由程序从宿主提供的消息字段或与消息、轮次相匹配的会话记录中只读提取；模型只接收标题核心。不能用线程更新时间、助手完成时间或处理时间代替。无法核验时不追加，仍按原规则处理标题。

新生成的核心保留原有 48 字符限制，完整标题最多 62 字符；既有更长标题继续保留，不截断。时间后缀与核心分别记录，手动和锁定保护比较完整标题，重复标题检测比较核心，避免时间造成错误锁定或掩盖重名。仅时间变化无需再次调用模型，稳定标题后的确认跳过也可以更新时间。关闭「显示最后发言时间」或执行 `configure --title-time off` 后，在下次正常检查时移除插件管理的后缀；`--title-time on` 恢复。用户自己添加的日期不会被当作插件后缀移除。

标题固定为「emoji 对象｜目标」：对象在前，目标在后，恰好一个全角分隔符。类别按持续产物选择，不随“修复”“发布”等临时动作切换。旧标题允许一次结构迁移，之后保留准确的对象措辞和主线；信息不足或已锁定时保留原名。

标题跟随最近几轮用户实质需求的主要语言，保留产品名和技术名词；助手回答、代码及引用原文不决定标题语言。偶尔一句外语不切换，持续换用另一种语言后允许迁移。语言判断由同一次 Luna 命名完成，不额外调用语言检测模型。更新规则不会立刻批量重命名历史话题，而是在下次正常检查时应用。

已有稳定标题且之前的内容基线仍一致时，新增的“好的”“收到”“继续”等纯确认可免模型保留，最多连续两轮，之后重新判断。附件、额外需求、漏处理的实质轮次、规则升级及手动标题保护不会被确认过滤器绕过；“推送”“修复”等动作词不作无条件跳过。

| 类型 | emoji |
| --- | --- |
| 内容制作 | 🎬 |
| 工具开发 | 🧩 |
| 对比调研 | 🔎 |
| 方法整理与文档 | 📝 |
| 日程安排 | 📅 |
| 页面设计 | 🎨 |
| 环境配置 | ⚙️ |
| 一般讨论 | 💬 |

默认参考最近 5 轮有文字的对话。只有问候或确认且没有实质目标时，直接保留标题，不调用模型。临时排错、术语解释、测试或「继续」不会自动变成新的主要目标。只有当前标题模糊、过时或主题明显转移时才修改。命名规则集中在 `../prompts/naming.md`。

## 控制方式

Windows 命令使用 `py -3` 替代 `python3`。从 0.4.0 起，Stop Hook 同步入队并立即返回，独立 worker 再检查轮次完成状态和标题。队列消费者串行处理请求；它与手动检查共用模型并发额度，默认上限 2，`max_parallel_workers` 可设为 1～8，排队与格式复核共享单次模型超时预算。未完成轮次会有界重排，过期事件保留原标题。Windows 沙箱身份需要另行配置当前用户的周期任务，详见 [后台队列与 worker](Windows队列与worker.md)。

可以直接让 Agent「暂停自动命名」「固定这个话题的标题」「恢复这个话题的自动命名」「预览这个话题的新标题」。插件内置的 Skill 会调用程序入口。

也可以在插件目录中运行：

```sh
python3 scripts/mogoo_codex_title.py doctor
python3 scripts/mogoo_codex_title.py status
python3 scripts/mogoo_codex_title.py usage
python3 scripts/mogoo_codex_title.py configure --model gpt-5.6-luna --service-tier fast
python3 scripts/mogoo_codex_title.py configure --model gpt-5.3-codex-spark --service-tier standard
python3 scripts/mogoo_codex_title.py rename <话题ID>
python3 scripts/mogoo_codex_title.py rename <话题ID> --apply
python3 scripts/mogoo_codex_title.py lock <话题ID>
python3 scripts/mogoo_codex_title.py unlock <话题ID>
python3 scripts/mogoo_codex_title.py pause
python3 scripts/mogoo_codex_title.py resume
```

`rename` 默认只预览。`--apply` 才写入标题，并读回核验标题元数据。它不保证桌面置顶缓存已刷新；桌面显示限制见 [发布验收](发布验收.md)。

Fast 是服务档位，不是另一个模型 ID。Spark 使用标准档位，模型本身以速度为重点。切换模型时若未指定服务档位，程序会清除旧模型的 Fast 设置，避免把不支持的档位传给新模型。

## 可选中转站配置

### 本地可视化设置

在插件目录运行：

```sh
python3 scripts/mogoo_codex_title.py settings
```

Windows 使用 `py -3 scripts/mogoo_codex_title.py settings`。程序会启动仅监听 `127.0.0.1` 的本地服务并打开系统浏览器，默认自动选择空闲端口；关闭命令进程即停止服务。`--no-browser` 只输出入口地址，Agent 可将返回的 URL 打开到 Codex 浏览器面板。`--port <端口>` 可指定端口。运行程序的 Python 环境需为 3.10 或更新版本。

页面自动读取当前配置，提供官方 / 中转站选择、模型、Fast 档位，以及中转站的 API 基础地址和密钥环境变量名。选择模式只更新草稿，点击「保存配置」后才写入与后台 Hook 共用的 `config.json`，下次命名生效。两种模式的已保存配置分别保留；修改模型时页面默认回到标准档位，可重新开启 Fast。

Windows 下，密钥环境变量名右侧提供「设置密钥」按钮。对话框显示目标变量名，输入默认隐藏；点击「保存密钥」会将值写入 `HKEY_CURRENT_USER\\Environment`，覆盖该用户变量的旧值，并读回核验。页面只接收保存结果，不回传密钥；关闭、取消或提交后清空输入。密钥不会写入插件配置、日志或命令行参数，用户环境变量也不是加密凭据仓库。其他系统目前仍通过系统环境变量手动配置。

保存密钥与保存模型配置是两次独立操作：密钥保存不会切换模式、改动模型或覆盖未保存的页面草稿。设置服务立即识别自己保存的新值，并通知 Windows 环境变更；已经运行的 Codex 仍需完全退出后重新启动。通过系统界面手动修改环境变量时，也需重启设置服务。对话框禁止覆盖 `PATH`、`CODEX_HOME` 等系统或运行变量，只允许为密钥使用独立变量名。

「重新读取」会放弃当前草稿并读取最新配置。若配置在页面打开后被命令行或另一个页面修改，保存会提示冲突，保留外部修改；重新读取后再编辑。命令行和页面共用校验与原子写入，并使用同一个配置锁；未知顶层配置和另一种模式的设置不被覆盖。

入口 URL 带一次设置服务的访问令牌，只用于本机设置接口；页面读取后会移除地址栏片段，刷新时可继续使用当前标签页。每次重新启动服务都会生成新令牌，旧入口不再有效。页面没有跨域写入权限，接口校验令牌、Host 和 Origin；整个页面不依赖远程字体、脚本或服务。它是插件自带的本地页面，不是 Codex 原生插件详情页开关，也不会调用模型或修改话题。

密钥环境变量检查只表示设置服务的环境中存在该变量，不能证明后台 Hook 的环境或模型连通性。通过对话框保存后必须完全重启 Codex。

### 命令行配置

默认 `provider=official`，保留原版的官方登录、Luna Fast 和独立隔离调用，不自动继承 Codex 用户配置中的 provider。中转站需要显式选择 `relay`，分别保存 API 基础地址、模型、档位和密钥环境变量名。官方模型与中转站模型独立保存，来回切换不会覆盖另一种模式的配置。

中转站须兼容 Codex 使用的 **Responses API、流式响应和 JSON Schema 输出**；只提供 `/chat/completions` 的服务不适用。`base_url` 填 API 基础地址（例如以 `/v1` 结尾），CLI 会请求其下的 `/responses`。协议与认证配置依据 [Codex 官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)。

在插件目录中配置：

```sh
python3 scripts/mogoo_codex_title.py configure --provider relay --base-url https://relay.example/v1 --api-key-env OIL_TITLE_RELAY_KEY --model <中转站支持的模型ID>
python3 scripts/mogoo_codex_title.py doctor
```

`OIL_TITLE_RELAY_KEY` 是环境变量名称，实际密钥通过环境变量提供；插件配置只保存变量名。地址禁止包含账号、密码、查询参数或片段。Windows 可用 PowerShell 设置用户环境变量，再完全重启 Codex，让后台 Hook 继承新环境：

```powershell
$relaySecret = Read-Host '输入中转站 API Key' -MaskInput
[Environment]::SetEnvironmentVariable('OIL_TITLE_RELAY_KEY', $relaySecret, 'User')
$env:OIL_TITLE_RELAY_KEY = $relaySecret
Remove-Variable relaySecret
py -3 scripts/mogoo_codex_title.py configure --provider relay --base-url https://relay.example/v1 --api-key-env OIL_TITLE_RELAY_KEY --model <中转站支持的模型ID>
```

上面的 `-MaskInput` 需要 PowerShell 7；其他环境请通过系统环境变量设置界面录入密钥。环境变量属于当前用户配置，不是加密凭据仓库。

中转站默认使用标准档位，不继承官方的 `priority`；中转站和选用模型支持 Fast 时，可在 relay 模式下显式执行 `configure --service-tier fast`。修改 `--model` 或 `--service-tier` 作用于当前选中的模式，也可在同一命令中通过 `--provider` 指定。

切回原版官方方式，或再次使用已保存的中转站配置：

```sh
python3 scripts/mogoo_codex_title.py configure --provider official
python3 scripts/mogoo_codex_title.py configure --provider relay
```

`status` 展示两种模式的配置；`doctor` 额外展示当前选中的模型、密钥环境变量是否存在，始终标记推理 `not_verified`。检查成功不代表中转站已通过模型实测。密钥缺失、接口失败或超时时保留原标题，不自动回退到官方账号。中转站配置也适用于独立归档评估，用量账本记录实际调用的模型和档位。

## 数据与并发边界

`usage` 汇总新版启用后的独立模型账本，按命名/归档和模型分组，展示调用尝试、Token、未知用量与处理结果。缓存命中包含在输入 Token 内，推理 Token 包含在输出内；未知不等于零，不换算账号额度。账本先记录启动，再记录模型返回与最终处理状态，校验失败、过期结果、格式复核及重名重试均保留独立记录。超时或进程中断只有已返回的用量可统计，其他标为未知。

账本保存在数据目录的 `usage/日期/`，仅含时间、用途、模型、话题 ID、用量、耗时和状态，不含标题、原文或错误详情。它不统计宿主管理 Agent；旧日志不合并进账本，避免迁移时重复计数。保留日志中的纯确认跳过数另列，日志轮转后可能少于历史总数。

配置、每话题状态和简短日志默认位于 `$CODEX_HOME/oil-codex-title`；未设置 `CODEX_HOME` 时使用用户主目录下的 `.codex/oil-codex-title`。改名后继续使用这个历史目录和 `OIL_CODEX_TITLE_DATA` 环境变量，不搬迁或重置数据。旧命令入口仍与新入口共用实现。未知配置字段会保留。

对话摘录在默认官方模式下传给原版使用的 Codex 模型服务；显式启用 relay 后传给所配置的中转站。插件不保存完整对话或命名提示词。临时模型会话使用 `--ephemeral`，输出临时文件用完删除。持久日志只记录状态、候选标题、简短理由与用量，每个话题按容量轮转。

后台 Hook 只返回空 JSON，不返回额外上下文、警告消息或续聊指令，因此命名内容不会追加到正常对话。Codex 仍可能显示 Hook 的执行状态或宿主自身产生的错误。

同一话题使用进程锁；处理请求的 worker 最多等待两个模型超时窗口加 20 秒，释放锁后重新判断最新轮次，避免漏掉快速连续对话的最后一次请求。等待发生在后台 worker，Hook 回调不等待命名。重复内容跳过模型调用；独立模型禁用 Hook，避免递归。同工作目录中发现与已记录标题重名时最多额外生成一次，仍冲突就返回 ambiguous_title。写入前重新读取话题，如果标题或对话已变化，就丢弃旧结果。官方改名 API 没有原子条件更新，最后一次检查与写入之间仍存在极短的并发窗口。

插件成功完成一次标题评估或写入后，才建立稳定基线；此后检测到外部改名会自动锁定。首次生成过程中，Codex 可能还在设置首轮标题，这类变化会丢弃旧结果，但不会自动锁定。首次处理前无法可靠区分宿主自动标题与用户手动标题，需要保留的标题请主动 `lock`。暂停或锁定不会取消已产生的模型费用。

## 兼容性与限制

- macOS：优先发现桌面 App 自带的 Codex；可用 `configure --codex-bin <路径>` 覆盖。
- Linux：保留 POSIX 内核锁，纳入跨平台自动化测试；桌面体验未实测。
- Windows：已适配原生启动、内核文件锁和 UTF-8；验收范围见 [Windows 安装与验证](Windows安装与验证.md)，不能把程序测试等同于桌面自动触发实测。
- 云端和 ChatGPT Work：不支持此本地话题适配器。
- 离线：可以查看配置和暂停，生成标题需要连接模型服务。
- 某些旧 CLI 无法读取桌面端的新存储格式；兼容性检查失败时保留原标题。
- 插件只响应安装之后实际触发的轮次，不自动扫描或批量修改历史话题。
- Hook 信任和功能开关由 Codex 管理；程序不会绕过或自行写入信任记录。
