# 命名与回归规范

## 插件名称与迁移回归

0.4.3 起对外名称统一为 `mogoo-codex-title`：插件清单标识和显示名、市场及条目、管理技能目录和 frontmatter、默认提示、设置页、README 图和安装命令保持一致。GitHub 仓库地址与上游历史记录按真实来源保留，不能用品牌替换生成不存在的链接。

改名不能仅修改显示文案。Hook 和技能须调用新的命令入口，`doctor` 只把新插件的定义计入就绪状态，不能因旧插件仍受信任而误报新插件可用。旧命令、数据目录、环境变量、计划任务和队列标识继续兼容，模型配置、锁定状态和用量记录共用原数据，不在源码改名时操作真实安装或信任状态。

Windows runner 优先选择新名称插件的完整缓存，并在同一身份内按语义版本选最新版；兼容旧市场中的新名称及历史缓存，跳过缺少入口或元数据不匹配的安装。已有 runner 需要用户安装后重新执行 `worker-setup` 更新；文档明确这一迁移步骤，不能把新模板测试通过等同于旧任务已经更新。

合成回归覆盖跨文件名称一致性、新旧入口读取同一配置与保护记录、新入口的 Hook 输出、只存在旧 Hook 时不误报就绪，以及 runner 的新旧缓存优先级、版本排序、不完整安装和无候选。普通回归只使用临时数据和模拟进程，不调用外部模型、不注册真实任务。结构验证、模型评测、自然 Hook 和桌面显示继续分别报告。

## Codex 程序发现与更新恢复

桌面程序位于会变化的版本目录，配置不能把一次解析出的原生路径当作永久入口。每次后台执行重新验证指定入口；旧路径不存在或无法启动时，自动查找 PATH 与当前用户的已知安装位置。Windows 额外检查 npm 和桌面程序目录，不依赖后台任务继承的新 PATH，不扫描其他用户或整个磁盘。候选只用参数数组执行 `--version`，不调用模型，不通过 shell，也不把原始 stderr 写入日志。

有效的手动入口保留优先级，设置新路径时严格校验，拼写错误不得悄悄保存另一个候选。npm 配置保留启动入口而非其解析结果；`--codex-bin auto` 清除固定入口，其他配置保持。运行时回退只返回当次可用程序，不改写配置、账号和 Hook 信任。版本检查通过不能代替 App Server、模型或真实 Stop 验收。

合成回归覆盖旧桌面目录被清理、新版本再次发现、后台 PATH 未刷新、npm 入口解析、多个桌面版本排序、不完整更新、损坏 / 超时 / 非 Codex 程序跳过、候选去重、全部不可用、有效手动入口优先、错误配置不落盘以及恢复自动模式。测试使用临时安装目录和模拟进程，不发布真实用户目录或账号配置。

跨平台 CI 曾发现模拟 Windows 查找时修改了共享的 `sys.platform`，使 macOS/Linux 的真实配置锁误调用 `msvcrt`。平台模拟必须限定在适配器自己的模块引用，不能改变文件锁与其他模块看到的宿主平台；配置测试继续使用真实宿主锁，不能通过跳过配置案例或模拟锁成功来掩盖问题。

## 官方默认与可选中转站

此 fork 用显式的 `provider=official/relay` 切换模型服务，旧配置默认仍使用原版官方 Luna Fast；两种模式分别保存模型和档位。中转站只保存 API 基础地址和密钥环境变量名，密钥不进入插件配置或命令参数。独立模型继续禁用 Hook、工具、插件、应用和多 Agent，不继承用户配置中的任意执行行为。中转站接口失败时保留标题，不自动使用官方账号兜底。配置在原子写入前校验，错误输入不能破坏已有配置。

此前的 `skills.max_context_tokens=1` 会使真实 CLI 在请求模型前报技能预算不足；移除该覆盖值，保留禁用插件和项目说明的隔离措施。普通回归覆盖旧配置默认行为、模式往返、独立档位、缺失密钥、无效配置保持原文件、超时和失败不回退，以及按实际中转站模型记账。测试仅使用合成数据，不读取用户真实账号配置。

真实 CLI 另连接本地模拟的 Responses SSE 接口，验证认证头、请求路径、模型、标准档位不发送 priority、禁止执行工具及 JSON Schema 输出；同时覆盖命名和归档的共享调用链。当前 CLI 会默认暴露图片与目标管理工具，独立进程显式关闭这两类工具；部分版本仍提供仅在 Plan 模式可用的 `request_user_input`，本流程使用默认模式，且命名提示词要求只输出 JSON。PowerShell 显式开启：

```powershell
$env:OIL_CODEX_TITLE_TEST_CODEX = (Get-Command codex.exe).Source
py -3 -m unittest discover -s tests -p test_relay_cli.py -v
```

此验收不消耗外部模型额度，也不等同于真实中转站模型、宿主 Stop Hook 或桌面显示验收；后者需要已安装且受信任的插件与用户提供的中转站配置。

## 本地设置页回归

设置页与命令行必须复用 `model_config_changes`，不能在网页服务内重写官方 / 中转站切换规则。两种入口写入前共用配置锁、验证与原子替换；页面用配置文件内容摘要识别外部修改，遇到冲突返回 409，要求重新读取后再保存。打开或选择选项只能修改页面草稿，保存才影响后台。

回归需启动真实的回环 HTTP 服务，覆盖默认只读、两种模式保存与往返、保留未知配置、错误输入不落盘、外部更新冲突、命令行修改可见、密钥只返回存在状态，以及无令牌、错误 Origin/Host 被拒绝。静态资源仅允许固定路径，不能通过 URL 读取其他文件。普通测试继续不调用外部模型。

浏览器验收使用独立合成配置目录，检查官方 / 中转站保存、草稿切换、外部修改提示、重新读取、刷新后持续访问与窄窗口布局。源码和提交中不得包含实测账号配置、访问令牌或浏览器截图；截图可保存在仓库之外。入口 URL 的令牌只代表该次设置服务，不是模型服务 API Key。

密钥对话框只将输入交给受同一令牌、Host 和 Origin 检查保护的本机接口，通过 `winreg` 写入 Windows 当前用户环境变量，禁止经过 shell 或保存到插件配置。接口只返回状态，不回显输入，失败响应使用固定说明。成功持久化并读回核验后才更新设置服务自身环境，已有 Codex 进程须重新启动。

测试覆盖密钥隐藏与取消清空、保存后状态更新且模式草稿不变、失败不泄露密钥、无令牌或跨域请求被拒绝，以及保留系统变量。真实 Windows 注册表验证只写独立的测试子项并清理，不改用户真实 Environment 项；浏览器验收使用仅修改测试服务自身环境的替代写入函数，不能把合成密钥写入用户真实配置。

## 标题承担什么信息

### 最后用户发言时间

时间由程序维护为 ` · MM-DD HH:mm`，标题模型只处理原有核心。优先读取消息创建时间；当前宿主接口没有消息时间时，通过会话记录匹配同一轮次和用户消息原文，只读取对应时间，不修改会话文件。带消息级元数据的记录优先使用 `create_time`；旧 CLI 记录必须通过轮次边界复核。尾部扫描有界，损坏、缺失、过长或不能匹配的记录不以当前时间兜底。

核心与显示标题分开记录。预览、重复内容和确认跳过都能计算后缀，但手动改名、锁定、暂停、归档和生成期间的新活动仍优先。时间本身不进入内容指纹，纯时间更新不调用模型，也不改变既有的最多两轮确认跳过规则。重名检测使用核心，手动保护使用完整显示标题，写入中断恢复同时核对待确认标题与待确认核心。写入失败不能提前覆盖上次成功的核心。

合成回归覆盖消息级时间、宿主会话记录和旧 CLI 边界、秒 / 毫秒 / ISO 时间、本机时区、缺失和损坏时间、扫描上限、核心长度、仅时间更新零模型调用、确认跳过、预览零写入、开关关闭、手动 / 锁定 / 暂停 / 归档保护、过期结果、重名和写入中断恢复。新显示设置在下一次正常检查应用，不迁移或批量评估历史话题。

统一结构为「类别 emoji + 对象｜目标」。旧规则把内容类型与动作混为一谈，且让重复泛词占据标题开头，导致同一项目内难以扫视。新规则先识别持续产物，再前置具体对象，以全角「｜」分隔核心目标；类别不随临时动作变化，对象名称不做同义替换。

旧标题没有分隔符或使用旧开发图标时，允许一次迁移，保留原有准确主线。已经符合格式的标题仍优先 keep。不能因为稳定规则拒绝迁移，也不能以迁移为由将整体目标缩成最近的测试、提交或子问题。新增合成案例分别检查迁移、迁移后的稳定性、视频修复与工具修复、方法整理与页面设计、对象前置；程序校验拒绝缺失或多余分隔符、空对象、空目标。实际批量检查发现模型偶尔将旧格式误判为合规：对这类 keep 最多复核一次；问候不复核，第二次仍信息不足则保留，不通过程序猜测对象强制改名。格式复核共享首次生成的超时预算，不因重试延长该次生成预算。

侧边栏外层项目已经提供分组上下文。标题优先说明模块、内容对象和当前持续目标，不默认重复外层项目名。emoji 只负责类别，不承担唯一标识。

需要项目名的例外：monorepo 内的子项目；从桌面或主目录操作某个具体项目；跨项目同步或迁移。跨项目同步可以让外层项目承担来源上下文，标题只写目标项目，不机械要求两端名称同时出现。模型名、公司名、文章与视频主题是任务内容，不因外层有项目而删掉。

新标题若以外层目录的精确等价名称开头（忽略空格、连字符与大小写），再做确定性去重；不处理 keep，不猜别名，不截断 MaplePay 这类不同名字，也不破坏“Maple 与 Cedar”的双端表达。

工作目录只提供末级名称作为弱线索，不发送完整绝对路径，也不把主目录用户名当成项目。当前没有稳定的宿主项目分组读取接口，目录名与实际侧边栏名称可能不同；模型必须以对话中明确的信息为准。

## 容易出错的决策

- 把最后一句“提交”“继续”当作新主线：先检查它是否服务于原来的模块目标。
- 为提高辨识度而重复外层项目名：先利用外层分组，再用模块和具体问题区分。
- 按全局标题重名强行改写：只在同工作目录、已被插件记录的标题范围内提示冲突。跨项目相同模块名称允许存在。
- 只有问候却让模型虚构“一般讨论”：对精确匹配的问候和确认先做确定性过滤，没有实质目标就保留。
- 把附件或 Skill 全文当作主要请求：剔除已知宿主包装，优先保留 My request 区域；正文仍作为数据处理。
- 把 Codex 首次自动标题当成用户手动改名：第一次成功评估后才建立保护基线。
- 把 metadata 写入等同于用户可见：分别检查写入、宿主自然触发、桌面缓存。缺少任何一项都不宣称整条链路已完成。

## 回归与评测

程序测试验证不会错误写入、不会把命名消息加到原任务、过期与重名结果会被丢弃，以及用户锁定规则。模型评测使用合成对话，检查主线延续、主题转移、分组省略、monorepo 例外和内容对象保留。

每次改变提示词都必须同步更新评测案例和策略版本，不能只手工改好一个标题。案例失败时先检查规范是否互相矛盾，再修改模型规则；不通过降低断言掩盖错误。

命名评测是单次、有限样本的规则验收。模型具有随机性，不能据此宣称所有真实任务都准确。完全相同的两个任务缺少区分证据时，保留原名并返回 ambiguous_title，不能编造日期、编号或新目标。

## 同组重名检查的范围

分组键使用工作目录的哈希值，不保存完整路径。旧版本日志没有分组键时，不把它当成另一个已知分组的冲突证据。检测到同组重名最多调用一次额外模型；仍有冲突则保留原名。并行任务可能同时产生尚未被记录的相同名称，因此这是减少重名的检查，不是全局唯一性保证。

## 安装文案验收

面向新用户的安装入口使用可直接发给 Codex 的自然语言指令，明确此 fork 的 GitHub 仓库 `MogooStudio/oil-codex-title` 与仓库内的 `mogoo-codex-title` 市场，由 Codex 下载并配置完整插件。不要默认用户已经克隆仓库或配置了名为 `personal` 的本地市场。README 与详细使用文档须保持一致，并保留 Hook 信任与实际触发的验收步骤。升级 fork 时同步提升插件清单版本，以免缓存复用旧实现；保留原作者出处和许可，不把新来源的验证结果写成上游已有结果。

文档检查案例：用户没有本地仓库、也没有个人插件市场时，仅复制安装指令即可让 Codex 确定仓库来源、安装范围和检查步骤；涉及界面信任时，指令应要求 Codex 告知具体操作。

## README 内容验收

主 README 须将 fork 的中转站支持、官方默认模式、可视化设置和 Windows 密钥对话框放入主要功能与操作说明，不能只在安装段落附带提及。安装与更新分别给出命令，迁移说明覆盖旧市场条目重新加载 Hook 的情况。区分「保存密钥」与「保存配置」，明确重启环境继承与 `doctor` 的验证边界；技能 README 同步模型服务和数据去向，示例只用合成地址与变量名。

模式切换优先给出可以直接发送给 Codex 的自然语言例句，覆盖中转站、官方账号、查询当前模式和打开设置页。说明已保存配置可复用、下次调用生效，首次配置和修改密钥另走设置流程；不要把插件详情页的启用开关描述成官方 / 中转站模式开关。

fork 的插件详情页开发者来自清单 `interface.developerName`，与 `author.name`、插件市场 `owner.name` 统一使用 `mogoo`；仓库与作者主页链接仍指向 `MogooStudio`。原作者出处和版权声明在 README 与 LICENSE 中保留。升级清单时检查这两类署名，不能把上游显示字段原样带入 fork。打包回归既断言发布者为 `mogoo`，也对比市场所有者、作者与界面开发者，避免三处一致但仍沿用旧名称，覆盖实际详情页曾显示上游作者的案例。

README 面向使用者，只保留功能价值、命名示例、带仓库名的安装指令、日常控制和影响使用的限制。实现流程、CLI 命令、配置路径、模型参数与评测证据放在详细文档，通过链接提供入口，避免每次发布都把验收细节堆回首页。

文案检查案例：不了解 Hook、App Server 或 CLI 的新用户，读完 README 也能说明插件的作用、复制安装指令并知道如何暂停；兼容性与用量限制仍须清楚可见。

## 跨平台与后台执行验收

先前用 macOS 本机测试代替了跨平台验证，未检查 POSIX 文件锁、Windows npm 入口和默认编码。后续涉及启动、进程、文件与 Hook 的修改，必须运行 Windows/macOS/Linux 矩阵；用真实子进程检查互斥与进程终止后的锁释放，用中文空格目录检查路径与 UTF-8。不因 Python 本身跨平台就宣称插件跨平台。除了 doctor，还须覆盖模型进程的启动参数与输出读取；只验证连接会漏掉 Windows 创建标志等在真实命名路径上的错误。

每轮完成检查以宿主返回的轮次状态为依据，不用固定睡眠猜保存时间。不同话题共享模型并发配额，排队算入模型预算，饱和或超时保留原标题；同一话题仍使用独立锁与写入前复查。代码测试、官方 CLI 连接、账号模型调用和桌面显示分别验收，不互相替代。

## 同步 Hook 与移交队列验收

Windows 后台执行不能只以 `DETACHED_PROCESS` 或新 PID 判断身份已切换；子进程可能仍沿用沙箱令牌。同步 Hook 只负责校验和入队，实际 worker 必须检查用户身份。沙箱入口依赖已配置的当前用户任务，仅授权本插件共享队列，不扩大 Codex 私有目录权限，也不绕过官方 Hook 信任。

借鉴队列机制时须覆盖重复投递与正在处理的请求同时出现的案例：不能用覆盖式移动替换活跃请求，也不能按文件年龄收回正在工作的 worker。回归覆盖真实跨进程内核锁、工作期间重复入队、孤儿请求恢复、有限重试、轮次未稳定重排、非法字段拒绝执行、错误身份拒绝消费，以及请求 / 完成记录无对话或密钥。程序测试不安装真实任务或修改真实 ACL。

保留显式官方 / 中转站模型选择与独立配置隔离，不因移交方案继承全局 provider 或恢复已知有问题的技能预算覆盖。后台错误只保留固定类别；`doctor`、任务配置标记及程序回归不能替代自然 Stop、任务运行、模型调用和桌面显示证据。

## 归档生命周期补充

增加周期任务时，必须先设计“不执行”的条件。只靠提示词说“不要重复”无法避免重复计费：模型之前先做归档状态检查、内容指纹判断和持久化尝试记录，程序负责门槛变化，模型只判断语义。失败、中断、不确定也不能每日自动付费重试。

归档状态是宿主事实，不能根据本地日志猜测成功；归档后恢复属于用户主动动作，本插件继续保护，避免恢复后立即再次归档。命名也必须遵守归档边界，避免旧 Hook 在用户归档后再次调用模型或写标题。

测试需覆盖：归档前零模型调用、生成期间归档、重复扫描、阈值变化复用分类、新对话使缓存失效、调用中断、终态恢复保护、宿主确认失败、分页完整性，以及陈旧保护快照拒绝写入。运行时间取真实轮次，不取标题更新或文件修改时间。定时管理 Agent 的唤起 Token 与候选评估 Token 要分别说明。

## 整体 Review 发现的三个边界

归档误用了适合标题概括的截断摘要，导致回答第 500 字后的待办不进入判断。今后不同决策分别定义信息完整性要求：命名可以压缩，归档必须保留选定近期轮次的完整用户消息和最终回答；超过预算时保留话题。升级时旧正向缓存也必须失效，但不能借此批量重新调用模型收费。

归档和暂停检查曾只覆盖入口与写入前，遗漏重名重试、内部格式复核和配额等待。把状态检查下沉到真正的模型进程启动前，各重试与队列出口共用同一检查；状态复核耗时也计入该次模型预算。测试需在第一次返回后和配额获得前改变状态，断言实际子进程启动次数，而非只断言没有写标题。

扫描曾只读取一次开关，暂停后仍继续下一项。定时调用必须使用 `--scheduled`，扫描中反复检查开关；显式暂停记录修订号，即使很快恢复，也不能让此前的扫描继续。手工预览与定时运行区分，首次未启用时仍允许用户明确请求的预览。

## 语言适配与稳定性

原提示词把中文示例、汉字长度与“中文为主”混在产品规则里；“格式正确必须保持”又会阻止语言迁移。文档使用中文不代表用户标题必须中文。今后语言规则与标题结构分别定义，检查两者是否冲突。

由现有命名模型根据近期用户的实质需求判断主要交流语言，不增加独立语言检测模型。助手回答、代码、日志、引用和待翻译原文不参与语言判断；产品和代码名称保留原文。单句外语不触发切换，混合且无主导语言时保留原语言；多轮实质交流已改变语言时允许一次迁移，不改变准确主线。格式、类别、手动保护、归档过滤仍共用原流程。

语言策略升级需递增 POLICY_VERSION，使下次正常检查能重新判断；不因此启动历史话题批量改名。合成回归必须包含：单轮非中文需求、双向语言迁移、不同语言的助手和长引用、代码日志、翻译对象、混合技术名词、短暂切换和稳定标题。使用独立案例文件运行，避免每次小改都重复调用全部模型案例：

```sh
python3 scripts/evaluate_naming.py --cases tests/fixtures/naming_language_cases.json
python3 scripts/evaluate_naming.py --cases tests/fixtures/naming_language_cases.json --live --workers 2 --output docs/naming-language-evaluation.json
```

程序测试只验证 Unicode 标题可读写及保护边界，语言识别质量必须另用显式模型评测检查，不能用提示词字符串断言代替。

首轮实测暴露出两处边界：语言票数相当时模型过度看重最后一条，拉丁字母标题容易超过原有长度限制。规则明确均衡时沿用原语言，补充非中文的短标题示例与字符余量。评测器必须保留校验失败的原始候选和用量，避免结构失败后丢失诊断证据。

复测发现语言已保持，但英文标题仍可能把 Fix 目标收窄为 Test。稳定性案例必须同时检查语言和持续目标；只看语言正确不足以通过。补充英文的修复后追加测试示例，与中文主线规则保持一致。

## 控制调用频率与完整记账

此前用“每轮结束检查”直接等同于“每轮调用模型”，使稳定标题后的确认也重复付费。确认跳过必须以已评估、格式合规且内容基线一致的标题为前提；只接受有限的纯确认表达，最多连续两轮。不能把动作词、附件、待处理的新需求或语言变更简单过滤。必须测试首次命名、基线缺失或变化、漏处理轮次、规则升级与手动保护。

用量不能只在写入成功后保存，也不能把内部重试汇总与逐次记录混加。新账本在真实子进程前登记尝试，解析进程输出后先保留用量，再处理 JSON 与标题校验；调用层记录结果，业务层记录过期、暂停、错误或采用结果。中断和未返回统计标为未知。回归需要覆盖成功、结果过期、格式错误、超时、启动失败、重试及无调用分支。

定时管理 Agent 与独立评估模型分别核算。长开发对话会让每次管理步骤重发大量历史，不能只优化评估提示词。用户认可独立管理后迁移原计划，用短上下文与轻量模型执行机械流程；程序设置扫描时间预算，管理 Agent 使用较长有界等待，不短轮询。预算不足保留未评估内容，下轮继续；不通过缩短归档证据、清缓存或放宽保护来节省 Token。

独立 Luna 的只读验收曾只执行保护名单刷新，却把未执行的扫描描述为成功。根因是关键步骤依赖模型逐项复述，且空输出没有被当作缺失证据。定时入口改用 `scan --guards-stdin`，在同一次程序调用中完成名单保存和扫描；管理侧只采信进程完成后的结构化结果，不手工重写名单，不把旧预览或无输出解释为零候选。回归覆盖新鲜报告、损坏或不完整名单拒绝执行、关闭状态零宿主访问；最终还须让实际管理模型跑一次无模型、无归档的端到端验收。
